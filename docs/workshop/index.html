The problem

Models invent locations

One comment on a line outside the diff, and GitHub rejects the whole review.

What we build

A typed finding + a grounding check

json_schema gives every finding a file, lines and a severity. Code drops what is not in the diff.

What you will see

Severities and DROPPED lines

Every dropped finding prints its reason in your terminal.

Add a gate, run it in GitHub Actions

PR diffinput
Contextrepo + spec
Promptrules
ModelOpenRouter
Groundingin the diff?
Gatecount blockers

The problem

The model’s verdict is not a decision

It can say “approve” while listing a CRITICAL finding.

What we build

A gate in code + a GitHub Action

Count blockers by severity, post one inline review, exit 1 when there are blockers.

What you will see

A red check on your pull request

Inline comments in your QuickBlog fork in 2–3 min. A human still merges.

3 · Gate + Action

Step 3 · the workflow reads hostile text

Four rules for a safe review workflow

1Trigger

pull_request, never pull_request_target

on: pull_request

2Permissions

Least privilege: only what posting a review needs

permissions: {contents: read, pull-requests: write}

3Fork guard

Skip runs from forks: no secrets for strangers

if: github.event.pull_request.head.repo.full_name == github.repository

4No PR text in run:

Never put ${{ }} with PR text into a script. Pass it through env:

env: { TITLE: ${{ github.event.pull_request.title }} }

The problem

One generalist misses whole classes

What we build

Agents as .md files + dedup

Security and spec-conformance run in parallel. The same file, lines and title merge into one finding.
